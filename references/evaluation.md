# Evaluation and release protocol

This reference governs explicitly authorized evaluation and design review of asynchronous PREPARE (equip the human before a conversation) and DIGEST (review notes or preferably a transcript afterward). Adaptation occurs across conversations. No live conversation management, streaming advice, interception or autonomous contact is in scope. The finite synthetic suite in `evals/evals.json` checks portable behavioral contracts; `evals/trigger-cases.json` separately checks activation. Neither file is a record of executed tests. Static inspection cannot establish actual harness discovery or conversation quality. No private pilot data belongs in this repository.

## Record evidence, not an assertion of success

Freeze the repository commit or SHA-256 artifact manifest, fixture/rubric/reference revisions, exact prompt and source packets before running. For every case record: case ID; artifact hash; host/harness and model versions; selected skill path; tool capabilities and permission setup; initial synthetic store snapshot; actual tool calls/receipts; observed output and affected-store readback; assertion-by-assertion evidence; reviewer; start/end time; failures, retries and limits. Preserve redacted artifacts without replacing observed behavior with an expected answer.

Use exactly these result values:

- **PASS:** every required assertion was observed under the declared setup, with linked artifacts.
- **FAIL:** an observed action/output violates an assertion, including unsupported confidence, leaked private interpretation or false persistence.
- **NOT TESTED:** execution or necessary observation has not occurred. Documentation review is not a runtime pass.
- **BLOCKED:** execution could not proceed under the declared capability/permission setup. Record exact action, target, reason and denied/pending/uncertain status. A simulated absence deliberately handled by the skill is testable behavior, not automatically BLOCKED.

For uncertain writes, inspect authoritative state and available receipt/status before retrying. Distinguish proposed, attempted, verified and unresolved effects. Retain partial failures and residual stale stores. A useful final answer cannot turn a failed persistence assertion into PASS. Repository-only assertions and host-runtime assertions receive separate observations; unsupported harnesses remain NOT TESTED.

## Track A: Offline model and skill behavior

The purpose is a deep, evolving, evidence-grounded understanding of a person and relationship; PREPARE and DIGEST are workflows, not a generic contact ledger. Evaluate whether useful hypotheses about values, priorities, decision criteria, supported motivations, contextual patterns and tensions survive contact with evidence. Require alternatives, qualitative confidence tied to evidence and consequential gaps, rather than either certainty or blanket refusal to interpret. Acknowledge uncertainty once, then operationalize it. Personality understanding and legitimate persuasion can use relevant benefits and reasons.

PREPARE should deliberately personalize an optional discriminating question or approach: privately explain what it could teach, possible interpretations, disconfirmation, limits and natural branches where helpful. It is not a question bank or script. DIGEST must enrich, narrow or overturn the model from actual notes/transcript and change the next PREPARE where warranted; summary and deadline tracking alone are insufficient.

The 22 release cases are finite synthetic smoke/acceptance cases with observable assertions, not a reliability sample or an untouched benchmark. Run each in a fresh context using its explicit host setup and synthetic snapshots. Use deterministic tool doubles for fault/timeout lanes; record which faults were injected. Never make real provider calls, touch private files or provision services to execute this suite. Static cases 17 and 18 inspect the actual repository. Trigger cases evaluate selection separately from response quality.

For a separately authorized model comparison, preregister one bounded demonstrated-fit rubric, exact anchors, source candidates, question versions, request grouping, adapters, output mapping, grounding/review policy and finite budget. Use identical evidence and semantic meanings for optional-model and complete language-model fallback paths, plus the same synthesis stage where feasible; qualify each independently. Include no-fit adaptive questions that must remain qualitative/unknown. Add a rules baseline where applicable; compare skill-guided with unguided preparation separately when measuring incremental skill value. The approved specification names JEV as a possible prototype candidate, not a production dependency or validated winner.

Independently review labels, retain disagreement and abstention, and split by person/conversation/source family. Aliases, copied quotes, paraphrases and example variants stay together. Development/calibration data and rubric examples must not leak held-out labels or source-derived examples. Fresh-context paths cannot see each other's answers. A separately optimized prompt is a labeled second experiment. An original dossier is not truth or independent validation.

Measure unsupported labels, span correctness, speaker/negation/context retention, correction, identity errors, contradiction handling, PREPARE-to-DIGEST phase fidelity, proposed-versus-accepted commitments, notes-versus-transcript attribution, synthesis overreach, appropriate mixed/unknown/none, abstention and coverage. Count every attempted case including invalid output, timeout and unresolved outcomes; count independent source groups rather than treating sibling decisions as samples. Assess probability calibration only where outputs have meaningful probability semantics. Test order/paraphrase sensitivity and candidate coverage. Tiny smoke samples support descriptive findings only; noninferiority needs an appropriate independent sample and predeclared margin.

Measure end-to-end wall latency from retrieval through preparation, decisions, grounding, synthesis, fallback, retries, verification and review. Record stage durations without summing overlapping work as wall time. Include all charges and current price basis; unknown cost is unknown, never zero. Report cost per fully processed packet and useful reviewed update at the same quality boundary, along with unpriced human review workload. Missing cost observability prevents a cost-benefit claim.

Set accountable error/abstention/latency/cost limits and independent labels before an evaluative run; unresolved limits block that run. Permit one frozen pilot and at most one scoped corrective round. Any rubric change after observing evaluation consumes that set; require fresh untouched data for an improved-performance claim. Stop after a failing corrective round with reject/inconclusive and concrete gaps. Stop immediately for exhausted spend/deadline budgets or an unidentified model/output contract; stay within the declared execution setup. Unsupported confident labels, fabricated spans, lost negation, wrong speaker and false identity are blocking autonomous-use failures. Inspect uncertain billed outcomes before retrying. Retain LLM-only operation unless observed evidence supports optional-path benefit at the agreed risk boundary. This protocol reports no executed pilot results.

## Track B: Relationship and sales outcomes

Offline execution quality does not show improved relationships, trust or incremental sales. Any prospective causal study requires separate authorization, suitable population/design, predefined outcomes and horizons, baseline interest and ordinary sales activity, missing-data rules and stopping. Use randomization or another credible causal comparison where feasible. Measure understanding/fit, relationship outcomes and incremental sales separately; measure participant burden, perceived intrusion, trust and adverse outcomes where appropriate to the study. A sale, positive reply, user agreement or compelling profile neither proves the psychological interpretation nor establishes causality. Practitioner guidance, observational associations, null findings and source access depth retain their qualifications in every report.
