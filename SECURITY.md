# Security reporting

GitHub supports private vulnerability reporting for this public repository without publishing an email address.

**Current status:** private vulnerability reporting is not enabled as of October 23, 2026. Enabling the repository setting is pending maintainer confirmation. Until then, do not put vulnerability details in a public issue.

Once enabled, use [Report a vulnerability](https://github.com/groktopus/relationship-intelligence/security/advisories/new) from the repository's [Security advisories](https://github.com/groktopus/relationship-intelligence/security/advisories) page. If the private form is unavailable, wait for that channel rather than posting the details publicly. There is no email reporting address.

A useful private report identifies the affected commit, harness/tool capabilities, expected and observed behavior, impact and minimal synthetic reproduction. Omit real relationship data and credentials. Distinguish an issue in the skill or bundled development tools from a host/provider issue.

This project currently maintains the latest main-branch content; there is no separate supported-version or response-time commitment. Findings will be assessed on their evidence and impact.

Maintainer setup: repository **Settings → Advanced Security → Private vulnerability reporting → Enable**. The feature must be verified enabled before this document is changed to describe the reporting form as active. See [GitHub's configuration documentation](https://docs.github.com/en/code-security/security-advisories/working-with-repository-security-advisories/configuring-private-vulnerability-reporting-for-a-repository).
